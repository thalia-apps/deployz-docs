Each deployment gets a default HTTPS address on `deployz.dev`. You can also add a custom domain on your customer's own hostname. This page covers problems with either one. For how custom domains work, see [Add a custom domain](/operate/custom-domains).

Problems on this page don't stop the application. While the secure address is being set up, the application is still reachable over its temporary address.

## The default HTTPS address stays in setup

**Symptom:** The deployment is running, but its secure address hasn't appeared. The dashboard says the application is "running and healthy over a temporary address", and the endpoint shows **Setting up**, **Waiting for certificate**, or **Activating HTTPS**. On the install page, your customer sees that the deployment is temporarily available at an address that's "not secure".

**Cause:** Setup is still in progress. Deployz requests the certificate for the default address, `d-<deployment-id>.deployz.dev`, during the install, and finishes the address once the deployment is running. Deployz manages the DNS records for this address, so your customer doesn't need to do anything. Setup moves forward about once a minute.

**Fix:** Wait. Deployz keeps trying for about 30 minutes. If the address is still not ready after that, the endpoint shows **Failed**. See the next section.

**Who acts:** nobody, while it's in progress.

## The default HTTPS address failed

**Symptom:** The endpoint row under **Infrastructure** shows **Failed**, and **Retry HTTPS setup** appears.

**Cause:** The default address didn't finish setting up within about 30 minutes. Deployz stops trying on its own at this point.

**Fix:**

**Who:** you (the vendor), in the Deployz dashboard.

1. Open the deployment.
2. Under **Infrastructure**, on the endpoint row, select **Retry HTTPS setup**.
3. Wait for the endpoint to show **Ready**.

The retry starts the setup again and keeps the existing certificate. **Retry HTTPS setup** appears only while the default address is in the **Failed** state, and not while the deployment's custom domain has also failed.

If the retry fails again, [contact support](https://share.hsforms.com/1dOsn_DJtRhq47DXIaRjeLw5auur) with the deployment ID.

## Read the custom domain card

The custom domain card shows the domain's status and, when something is wrong, a message with a title and a short explanation. You and your customer see the same card. Only you can remove or add a domain.

| Status | What it means |
| --- | --- |
| **Setting up** | Deployz is requesting the certificate for the domain. The card says "Requesting a certificate for this domain…" |
| **Waiting for DNS** | The card lists the two DNS records your customer needs to create. See [A custom domain is waiting for DNS](#a-custom-domain-is-waiting-for-dns). |
| **Connecting** | The records are in place. The card says "Domain verified. Deployz is configuring HTTPS." |
| **Active** | The domain serves the application over HTTPS. |
| **Needs attention** | The setup stopped. Deployz doesn't retry it. See [A custom domain needs attention](#a-custom-domain-needs-attention). |
| **Removing** | The domain is being removed. It stops routing once removal finishes. |

While the domain is **Waiting for DNS** or **Connecting**, the card can also show the result of the latest check. These messages describe progress, not a failure:

| Message | What to do |
| --- | --- |
| **Verification record not found** | Your customer checks that the **Verify ownership** record exists and matches the card exactly. |
| **Domain isn't pointing to this deployment** | Your customer updates the **Route traffic** record to the value on the card. |
| **HTTPS isn't reachable yet** | Wait. The load balancer may still be setting up, or the deployment may not be running. |
| **This deployment isn't running** | Domain setup continues once the deployment is running again. Fix the deployment first. |
| **We couldn't connect this domain** | Check the DNS records, then select **Check now**. This message also appears after a domain change timed out. See [A custom domain update timed out](#a-custom-domain-update-timed-out). |

## A custom domain is waiting for DNS

**Symptom:** The custom domain card shows **Waiting for DNS** and lists two DNS records.

**Checks:** Ask your customer to confirm that both records exist at their DNS provider, with the exact name and value shown on the card:

| Record | Purpose |
| --- | --- |
| **Verify ownership** | A `CNAME` record that proves the domain is theirs, so AWS can issue the certificate. |
| **Route traffic** | A `CNAME` record that points the hostname at the deployment's load balancer. |

New DNS records can take some time to become visible.

**Who:** your customer, in their DNS provider. You or your customer can select **Check now**.

**Fix:** Your customer creates or corrects the records. Deployz checks again automatically every few minutes. To check right away, select **Check now** on the custom domain card. **Check now** can run once every 30 seconds. See [Create custom domain DNS records](/customers/custom-domain-dns) for the customer's steps.

## A custom domain needs attention

**Symptom:** The custom domain card shows **Needs attention** with one of these messages:

| Message | Likely cause |
| --- | --- |
| **The HTTPS certificate couldn't be issued** | The certificate authority didn't accept the domain. Check the domain name for typos. |
| **Deployz couldn't configure HTTPS** | Your customer's AWS account doesn't currently allow Deployz to complete the domain setup. Ask your customer whether a policy in their account blocks it. See [The connector lacks permission](/troubleshooting/install#the-connector-lacks-permission). |
| **This deployment isn't running** | The deployment isn't running. Fix the deployment first. |
| **We couldn't connect this domain** | The setup didn't complete. Check the DNS records with your customer. |

Deployz doesn't retry a domain in this state. Your card says "Remove this domain, then add it again to start over." Your customer's card says "Ask the application owner to remove this domain and add it again."

**Who:** you (the vendor), signed in to Deployz, on the deployment's install page.

**Fix:**

1. Fix the cause the message points to.
2. Open the custom domain. In the dashboard, select **Manage custom domain** on the deployment.
3. Select **Remove domain**, then confirm. Your customer's DNS records aren't deleted automatically.
4. Add the domain again, with the corrected name if needed. Your customer then creates the new records the card shows.

## A custom domain update timed out

**Symptom:** A custom domain stays in **Setting up**, **Waiting for DNS**, or **Connecting** longer than expected. In **Waiting for DNS** or **Connecting**, the card can show **We couldn't connect this domain**.

**Cause:** The Deployz connector didn't finish a domain change within the allowed time. Deployz records this as `DOMAIN_OPERATION_TIMEOUT`. It doesn't fail the deployment, and the deployment's recovery panel doesn't show it. The domain keeps its status, and the deployment itself isn't affected.

**Who:** you or your customer.

**Fix:** Wait for the next automatic check, or select **Check now** on the custom domain card. If the domain then shows **Needs attention**, follow [A custom domain needs attention](#a-custom-domain-needs-attention). If the timeout keeps happening, check the connector. See [Fix connector problems](/troubleshooting/connector).

## Change a custom domain

A deployment has one custom domain. You can't edit its hostname. To change it, remove the domain, then add the new one.

<Warning>
  When you remove a domain, it stops routing to the deployment right away. People who use that hostname can't reach the application until the new domain is active. The default address keeps working throughout.
</Warning>

**Who:** you (the vendor), signed in to Deployz, on the deployment's install page.

1. Select **Remove domain** on the custom domain card, then confirm.
2. Wait until the domain is removed.
3. Select **Set up custom domain**, enter the new hostname in **Domain**, and select **Add domain**.
4. Send your customer the two new DNS records.

Deployz accepts subdomains only, such as `app.example.com`. It doesn't accept root domains, such as `example.com`, or wildcard domains.
