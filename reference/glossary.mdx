The terms Deployz uses in the dashboard, on the install page, and in this documentation, in alphabetical order. Status labels are in bold, as they appear in the dashboard.

## A

**Analysis:** Deployz's check of an application's repository. It works out how to build, start, and host the application, and lists anything you need to change or answer. See [Fix analysis problems](/troubleshooting/analysis).

**Analysis failed:** An application status. Deployz couldn't read or analyze the repository. The application's **Overview** shows the reason and **Re-analyze application**. See [Fix analysis problems](/troubleshooting/analysis).

**Application:** The software you deploy with Deployz, connected to a GitHub repository. Each application has releases, and each release can run in many deployments. See [Key concepts](/concepts).

**Application stack:** The AWS CloudFormation stack that holds one deployment's application, with its network, load balancer, and any database, cache, and file storage it needs. Its name starts with `deployz-app-`. The connector has CloudFormation create it in the customer's AWS account. See [AWS resources Deployz creates](/reference/aws-resources#application-stack).

## B

**Billing paused:** A production deployment that was live, but has now failed or lost contact with its connector, isn't counted toward your bill. Billing resumes when the deployment is live again. See [Pricing and billing](/account/billing).

## C

**Connector stack:** The AWS CloudFormation stack your customer creates with Quick Create during the install. It creates the Deployz connector, its roles, and the execution role CloudFormation uses for the application stack. Its name starts with `deployz-bootstrap-`. See [AWS resources Deployz creates](/reference/aws-resources#deployz-connector-stack).

**Custom domain:** A domain name your customer owns, such as `app.example.com`, that you add to a deployment in addition to its default address. Traffic to a custom domain goes directly to the load balancer in the customer's AWS account. See [Add a custom domain](/operate/custom-domains).

**Customer:** A company or person that runs your application in their own AWS account. Customers don't have a Deployz account. They use the install link or invitation you send them. See [Key concepts](/concepts#customer).

**Customer override:** A configuration value you set for one customer that replaces your application's default. Overrides are stored per customer and application, so they apply to all of that customer's deployments of the application. See [Change a customer's configuration](/operate/configuration).

## D

**Default address:** The permanent HTTPS address every deployment gets, in the form `https://d-<deployment-id>.deployz.dev`. Traffic to it passes through the Deployz Cloudflare network. See [Application traffic](/customers/security#application-traffic).

**Delete retained data:** The action that deletes the resources a removed deployment left behind: the database, without a final snapshot, the file storage bucket, application secrets, certificates, and the remaining network. It runs through the connector, so the connector must be online. It can't be undone. See [Remove a deployment](/operate/remove).

**Deployment:** One copy of your application running in one AWS account, in one Region and at one size. A test deployment is also a deployment. See [Deployment status and health](/operate/deployment-status).

**Deployz connector:** A small AWS Lambda function in your customer's AWS account, created by the connector stack. It connects out to Deployz, carries out installs, updates, and removals, and reports status. See [The Deployz connector](/how-it-works#the-deployz-connector).

## F

**Failed:** A deployment status that means an operation didn't complete. The badge names the operation: **Install failed**, **Update failed**, or **Removal failed**. After a failed update, the previous release keeps running. The deployment page explains why and what to do next. See [Troubleshooting](/troubleshooting/overview).

**Failure code:** A stable code, such as [`MISSING_SECRET`](/reference/failure-codes#missing_secret), that identifies why a deployment failed. See [Failure codes](/reference/failure-codes).

## H

**Health check:** The request the load balancer sends to your application's health check path to decide whether it's running. If analysis finds no health route, Deployz checks `/` and accepts a redirect as a healthy response. See [How Deployz decides a deployment is healthy](/operate/deployment-status#how-deployz-decides-a-deployment-is-healthy).

## I

**Install:** The first deployment of an application into a customer's AWS account. Later changes are updates. See [Install the application](/customers/install).

**Install link:** A link that lets a customer install your application in their AWS account. There are two kinds:

- **The application's install link** is reusable. You share the same link with any number of customers, and each confirmation creates a new customer record and a new deployment. Each application has one live install link at a time, which you can disable, enable, regenerate, or revoke. See [Share an install link](/share/install-links).
- **A deployment's own install link** is on its deployment page. It's valid for 30 days. When you issue a new install link, the address stays the same, but the connection code and the connector credential change, and the link is valid for 30 more days. A connector stack or Quick Create link started with the old values stops working. See [Reconnect or update the Deployz connector](/operate/connector).

**Install page:** The page your customer opens from an install link or invitation. On it, they review what will be created and the estimated AWS cost, choose a Region and size, enter any settings you asked for, and connect their AWS account. It then shows the install's progress. See [Install the application](/customers/install).

**Installation ID:** An identifier created inside your customer's AWS account when they create the connector stack. Deployz uses it to tag and name the deployment's resources, which keeps them apart from other deployments in the same account. It isn't part of the Quick Create link. See [Security and AWS access](/customers/security).

**Invitation:** A private, single-use install link for one specific customer. It expires 30 days after you create it, and you can revoke it while it's active. See [Invite a specific customer](/share/invitations).

## L

**Live:** A deployment status. The connector verified that the application is running and healthy. As an application status, **Live** means the application has customer deployments and none of them needs attention. See [Deployment status and health](/operate/deployment-status).

## N

**Needs attention:** A deployment status that means a deployment is installed but something is wrong. The badge names the reason:

- **Lost contact:** the connector stopped checking in.
- **Not responding:** health checks are failing.
- **Degraded:** some health checks are failing, but the application is still reachable.

As an application status, **Needs attention** means at least one customer deployment has failed or needs attention. See [Deployment status and health](/operate/deployment-status).

**Needs input:** An application status that means Deployz needs a change, a decision, or a value from you before the application can be deployed. See [Fix analysis problems](/troubleshooting/analysis).

**Not analyzed:** An application status that means analysis hasn't started yet. Select **Analyze application** to start it.

## O

**Organization:** Your company's account in Deployz. It holds your applications, customers, deployments, and billing. Each person in it has a role: owner, admin, or member. See [Organization and team](/account/organization-and-team).

## P

**Permissions boundary:** An AWS IAM policy that sets the most a role can do, even if another policy grants more. The connector role has one, and every IAM role in the application stack must carry the application role boundary. See [Security and AWS access](/customers/security#application-role-boundary).

**Preview:** A label this documentation uses for features that work but haven't been fully qualified on AWS. The dashboard doesn't show it. Queues and scheduled jobs are Preview features.

## Q

**Quick Create:** An AWS CloudFormation page that opens with the template and its values filled in, so your customer can review and create the connector stack in one step. See [Connect your AWS account](/customers/install#connect-your-aws-account).

## R

**Ready to share:** An application status. The test deployment passed, and you can create the install link.

**Ready to test:** An application status. The analysis passed with no required changes, and the application has no test deployment yet.

**Recoverability:** What a failure needs before it can be fixed: whether it can clear on its own, needs a change from you or your customer, needs Deployz, or can't be retried as is. See [Troubleshooting](/troubleshooting/overview).

**Recovery panel:** This documentation's name for the panel at the top of a deployment page when something fails. The dashboard doesn't label it. It shows what happened, the impact, the cause and fix, and **Technical details**. See [Troubleshooting](/troubleshooting/overview).

**Region:** The AWS Region a deployment runs in. You can't change it after the deployment is created. See [AWS Regions](/share/regions).

**Release:** A built, versioned copy of your application, created from your repository. The version is its label. You deploy releases to customers. A release can later show **Unavailable** when its build is no longer available. See [Create a release](/releases/create).

**Remove a deployment:** The action that deletes a deployment's application and most of its networking from the customer's AWS account. It keeps the database, its credentials, the file storage bucket, and the network parts the database uses until you delete retained data. The connector stack stays until your customer deletes it. See [Remove a deployment](/operate/remove).

**Removed:** A deployment status. The deployment was removed. Retained data may still exist.

**Retained data:** The resources that remain in a customer's AWS account after you remove a deployment: the database, with deletion protection on and AWS automated backups continuing, its credentials, the file storage bucket, and the network parts the database uses. Certificates, the cache, and the application's configuration secret are deleted at removal. These resources can keep costing money until they're deleted. See [AWS resources Deployz creates](/reference/aws-resources).

**Rollback:** Returning a deployment to the release it ran before the current one. A rollback doesn't reverse database migrations. See [Roll back a deployment](/operate/rollback).

## S

**Setting up:** A deployment status. Your customer started the install, and Deployz is connecting to their AWS account, creating infrastructure, or verifying the application. **Setting up · Slow to connect** means the connector hasn't connected 15 minutes after the install started.

**Size:** The preset that sets the container, database, and cache capacity of a deployment: Small, Medium, or Large. You can't change it after the deployment is created. See [Sizes and AWS cost](/share/sizes-and-cost).

**Size presets:** The application's sizes on **Configuration** › **Size presets**, with the default size and the minimum size. Customers can choose only sizes at or above the minimum. See [Sizes and AWS cost](/share/sizes-and-cost).

## T

**Technical details:** The collapsed section on a page that holds the raw detail behind a status or failure, such as the failure code, the AWS resource, and error messages. On the customer's install page, the review step calls it **Technical details**, and the progress view calls it **Deployment details**.

**Test deployment:** A free deployment into an AWS account you control, using the same flow your customers use. You run one before you share an install link. While it runs, the application status is **Testing**. If it fails, the status is **Test failed**. See [Run a test deployment](/share/test-deployment).

## U

**Update:** Moving an existing deployment to a different release with **Deploy update**. See [Deploy an update](/operate/deploy-update).

**Update available:** A filter on the **Deployments** list for live deployments that have a newer ready release. These deployments keep the **Live** badge. See [Deployment status and health](/operate/deployment-status).

## V

**Vendor:** The software company that uses Deployz to deploy its application into customers' AWS accounts. In the customer guide, the vendor is called "your software provider". See [How Deployz works](/how-it-works).

## W

**Waiting for customer:** A deployment status. You created the deployment, and your customer hasn't started the install yet.

**Worker:** A long-running background process of your application, such as a job runner. It runs next to the web service, from the same container image with its own start command, and receives no web traffic. See [Background workers](/prepare/requirements#background-workers).
