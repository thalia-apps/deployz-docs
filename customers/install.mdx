Installing has four parts: you review and confirm the plan on the install page, verify your email with a code, approve the connector stack in your AWS console, then follow the progress on the install page until the application is ready.

Before you start, complete the checks in [Before you install](/customers/before-you-install).

## Review and confirm the plan

**Who:** you, on the install page your software provider sent you.

The page is titled **Install** followed by the application name, and shows who published it and which release you'll install. Work through it from top to bottom.

<Steps>
  <Step title="Choose the AWS Region">
    Under **AWS Region**, select the Region the application will run in. If your software provider recommends one, it's preselected and marked **Recommended**. You can't change the Region later.
  </Step>
  <Step title="Choose the size">
    Under **Size**, select **Small**, **Medium**, or **Large**. Your software provider may offer only some of these. A larger size runs the application on more capacity and costs more. The size your software provider recommends is preselected and marked **Vendor recommended**. Here, "vendor" means your software provider. You can't change the size later.
  </Step>
  <Step title="Review what will be created">
    Check **What Deployz creates in your AWS account**, the estimated AWS cost for your Region and size, and **What Deployz can access**. The cost estimate appears after you select a Region. The page also says which resources stay in your account if the deployment is removed later. Select **Security details** to read the full security information in a new tab.
  </Step>
  <Step title="Enter the application settings">
    If the page shows **Application settings**, enter each required value. A counter shows how many settings are complete. Secret values are sent to Deployz over HTTPS and stored encrypted until your AWS account connects. See [Security and AWS access](/customers/security).
  </Step>
  <Step title="Enter your details">
    Under **Your details**, enter your name and email. This section doesn't appear if your software provider sent you a personal invitation, because the invitation already names you.
  </Step>
  <Step title="Continue to setup">
    The page confirms the size and Region you're approving. Select **Continue to setup**. Nothing is created in your AWS account yet.
  </Step>
</Steps>

If **Continue to setup** is unavailable, the line under it says what's missing, for example a Region or a required setting. If the page says the Region can't be installed right now, select a different Region.

If the page shows **Setup could not continue**, follow the message under it. For example, if the plan changed after you reviewed it, the page shows the updated plan. Review it, then select **Continue to setup** again. If the message asks you to contact your software provider, they need to fix something before you can continue.

After you continue, the page opens a new address for your deployment. Keep this address. You return to it to follow the progress. The page asks for an emailed code before it shows anything beyond the application and publisher names, so a copy of the address alone doesn't give someone access.

## Verify your email

**Who:** you, on the install page.

Before you can connect your AWS account, the page asks you to verify your email. This proves that you're the person your software provider set the deployment up for.

<Steps>
  <Step title="Send the code">
    Under **Verify your email**, enter the email address your software provider has for this deployment. For a link you opened yourself, that's the email you entered under **Your details**. Select **Send code**.
  </Step>
  <Step title="Enter the code">
    Check your inbox for a message with the subject "Your sign-in code for" followed by the application name, sent by Deployz. Under **Enter the code**, enter the 8-digit code and select **Continue**. The code expires after 10 minutes, and you get 5 attempts for each code.
  </Step>
</Steps>

The page gives the same answer for every email address and never says whether an address has access. If you enter a different address, the page looks the same, but no email arrives.

To get another code, select **Send a new code**, which is available 60 seconds after the last one. To start over with a different address, select **Use another email**.

### If the code does not arrive

1. Check your spam or junk folder for a message from Deployz.
2. Make sure you entered the email address your software provider has for you. A different address gets no email, and the page doesn't tell you. Select **Use another email** to try another address, or ask your software provider which address they have.
3. Wait 60 seconds, then select **Send a new code**. You can request up to 5 codes per hour for one address.
4. After 10 wrong codes for one address within an hour, the page asks you to wait one hour before you request a new code.

If none of this works, ask your software provider to check the email on your customer record.

The first email you verify becomes the owner of the deployment. If your software provider later changes the email on your customer record, the owner doesn't change.

You stay signed in until the page has been idle for 30 minutes, or for 12 hours at most. The page shows **Signed in as** your email and a **Sign out** button.

## Connect your AWS account

**Who:** you, on the install page and then in your AWS console.

The page is now titled **Deploy** followed by the application name and **to your AWS account**. It shows the Region and release, the estimated AWS cost, **What will be deployed** (select **View AWS resources** for the complete list), and the data that stays after removal.

If the page shows an **Invitation expires** date, connect your AWS account before then. After that date, the page says **This install link has expired**. Once your AWS account has connected, the link keeps working so you can follow the progress. When your session ends, the page asks for a new code.

If **Connect AWS account** is unavailable and the page says your software provider hasn't published a setup template yet, contact them for a working link.

<Steps>
  <Step title="Sign in to the right AWS account">
    In the same browser, sign in to the AWS account you chose, with an identity that can create CloudFormation stacks and IAM roles.
  </Step>
  <Step title="Select Connect AWS account">
    Select **Connect AWS account**. Your AWS console opens in a new tab on a CloudFormation Quick Create page. Nothing is created until you approve it there.
  </Step>
  <Step title="Check the account and Region">
    In the AWS console, check that you're in the intended account and that the Region matches the one you chose on the install page.
  </Step>
  <Step title="Create the stack">
    Leave the stack name and parameters as they are. Acknowledge that AWS CloudFormation might create IAM resources, then create the stack. This creates the Deployz connector stack, whose name starts with `deployz-bootstrap-`.
  </Step>
  <Step title="Return to the install page">
    Go back to the install page tab. It shows the progress of the setup in your account.
  </Step>
</Steps>

Under **Technical details** on the install page, you can see these steps, the AWS identity requirement, a link to **Security & permissions details**, and an **Installation reference** to quote if you contact your software provider.

## Wait for the connector to connect

While the stack is being created, the page shows **Setting up your AWS connection**. If you closed the AWS tab, select **Open AWS setup** to open it again. **Deployment details** shows the expected stack name and an **Open AWS CloudFormation** link.

If the connector hasn't connected after about 15 minutes, the page shows **Still connecting**. The setup in your account may still be running, or it may have failed before the connector started.

1. Select **Open AWS CloudFormation** under **Deployment details** and check the connector stack.
2. If the stack failed, or you closed the setup before creating it, select **Retry connection**.

**Retry connection** starts a new attempt with a new single-use code, and the page shows **Connect AWS account** again so you can create the stack. If a connector stack from your earlier attempt is still in your account, the page instead shows **Reconnect the existing connector**. Update that stack, and don't create a second one. See [Update the connector stack](/customers/update-connector#reconnect-the-connector).

## Follow the progress

**Who:** Deployz does the work. You can watch on the install page.

Once the connector connects, the page shows a step list. Only the steps that apply to this application appear. The page updates on its own, so you don't need to reload it.

| Step | What happens |
| --- | --- |
| **Connect your AWS account** | The connector stack is created and the connector connects to Deployz. |
| **Create infrastructure** | The network, and the database and storage or the Redis cache if the application uses them. |
| **Start application** | The application starts. Database migrations run here if the application has them. |
| **Check application** | Deployz checks that the application is reachable and healthy. |
| **Set up HTTPS** | Deployz sets up the application's secure address. |
| **Ready** | Everything is set up and the application passed its health checks. |

The heading above the list follows the stage: **Connecting your AWS account**, **Creating application infrastructure**, **Checking your application**, and **Your application is ready**. The current step shows what's happening now. **Deployment details** holds the detailed step list, the AWS activity, and the resources being created.

AWS can report a failed resource before the deployment stops. When it does, the page shows **AWS reported a problem** with the message from AWS.

If **Set up HTTPS** shows "Waiting for a custom domain to be added," the application is running and healthy but doesn't have a secure address yet. If your software provider has added a custom domain, create its DNS records. See [Create custom domain DNS records](/customers/custom-domain-dns). Otherwise, contact your software provider.

If the page shows "Status updates unavailable. Showing the last confirmed state.", Deployz can't get new status from your account right now. The page keeps the last stage it confirmed.

### If the deployment fails

The page shows **Deployment failed** with what happened and whether anything from the attempt remains in your account. Unless the page says otherwise, no action is required from you: your software provider is notified and can retry the deployment. If something in your AWS account or setup must change first, such as a quota or an organization policy, the page says so. Make the change, then contact your software provider to retry.

This page has no retry for a failed install. Your software provider starts it. Keep the page open or come back to it later: it checks for a new attempt about once a minute and shows its progress.

## Open the application

When the page shows **Your application is ready**, select **Open application**.

Under **Access**, the page shows the address where the application is available. By default, this is a permanent HTTPS address that Deployz provides on `deployz.dev`, so you don't need to change any DNS. Once a custom domain is active, **Access** shows the custom domain instead.

Traffic to the `deployz.dev` address passes through the Deployz Cloudflare network, where HTTPS ends, before it reaches the load balancer in your account over a new HTTPS connection. If you don't want your application traffic to pass through Deployz, ask your software provider to add a custom domain, and use only that address. See [Application traffic](/customers/security#application-traffic).

While the application is being checked, **Access** can show a temporary address with "not secure". That address may change. Wait for the HTTPS address before you share or bookmark it.

If your software provider sets up a custom domain for the application, a **Custom domain** card on this page shows the DNS records to create. See [Create custom domain DNS records](/customers/custom-domain-dns).

Once your AWS account has connected, the page notes that this install link has been used. To install again, ask your software provider for a new link.

## Come back to the deployment page

**Who:** you, on the same address, after you verify your email.

The address keeps working after the install, so you can return to check on the deployment. You sign in with a new code when your session has ended. The page shows:

- **Deployz connector:** whether the connector is connected, when it last contacted Deployz, its version, and whether an update is available. If one is, select **Update connector**. See [Update the connector stack](/customers/update-connector).
- **AWS location:** the AWS account, Region, and connector stack. Select **Open in AWS** to open the stack in CloudFormation.
- **Activity:** recent events for the deployment.

Select **Sign out** to end your session.

## If the link does not open

| The page says | What to do |
| --- | --- |
| **This install link has expired** | Ask your software provider for a new link. |
| **This install link was revoked** | Ask your software provider for a new link. If the message says your software provider removed this installation, they removed the deployment before it was installed, and you don't need to do anything in AWS. |
| **This link isn't valid** | Check that you used the complete link. For a personal invitation, the part after `#` is required. Otherwise ask your software provider for a new link. |
| **This application cannot be installed** | The message under it says why, for example that the link was revoked, expired, or already used, or that the application isn't available right now. Contact your software provider. |
| **We can't load this page right now** | Deployz couldn't load the page. Your link is still valid. Select **Try again**, or come back a little later. |
