The application runs in your AWS account, so AWS bills you directly for the resources it uses. Deployz doesn't bill you. Any fees for the application itself are between you and your software provider.

## What runs in your account

Each deployment creates its own set of resources. The install page lists the ones this application needs under **What will be deployed**.

| Resource | When it's created |
| --- | --- |
| Application containers (Amazon ECS on AWS Fargate) | Always, one or more services |
| Application Load Balancer | When the application serves web traffic |
| NAT gateway, with an Elastic IP address | Always, as part of the application's own network |
| S3 bucket for stored files | Always |
| Background workers (Amazon ECS on AWS Fargate) | When the application runs background processes |
| Queues and dead-letter queues (Amazon SQS) | When the application uses them |
| Schedules (Amazon EventBridge Scheduler) and the tasks they start | When the application has scheduled jobs |
| Database (Amazon RDS for PostgreSQL or MySQL) | When the application needs one |
| Cache (Amazon ElastiCache for Valkey) | When the application needs one |
| Deployz connector (AWS Lambda, run every minute by an Amazon EventBridge rule) | Always |

The size you choose sets the capacity of the containers, the database, and the cache. You can't change the size after you continue to setup.

## The estimate on the install page

The install page shows an **Estimated AWS cost** per month for the Region and size you select. It's a rounded range, not a quote:

- It uses on-demand AWS prices for one instance of each resource, running all month.
- Prices come from a US East (N. Virginia) baseline, adjusted by a factor for your Region.
- The total is rounded to steps of $5.
- It doesn't include usage-based charges, such as outbound internet data transfer, data transfer between Availability Zones, load balancer capacity, data processed by the NAT gateway, files stored in S3, and database storage growth and backups. Queues, schedules, and one-off tasks are billed by usage only.
- It doesn't price smaller charges either: Secrets Manager secrets, CloudWatch Logs, CloudWatch alarms, the NAT gateway's Elastic IP address, and the Deployz connector's Lambda, EventBridge, and Systems Manager usage.

If some resources can't be priced, the page says the estimate is incomplete. Your actual charges depend on usage.

## Costs after removal

When your software provider removes the deployment, some resources stay in your account so that your data isn't lost: the database (with its automated backups), its credentials, the storage bucket, the network parts the database uses, and the Deployz connector.

<Warning>
  Retained resources keep costing money in your AWS account until they're deleted.
</Warning>

To stop these charges, ask your software provider to delete the retained data, or delete the resources yourself in the AWS console. See [Remove the application](/customers/remove). For the full list of what remains, see [AWS resources Deployz creates](/reference/aws-resources#what-remains-after-removal).

To track what the application costs, you can filter AWS Cost Explorer by the `deployz:installation` tag after you activate it as a cost allocation tag in the AWS Billing console.
