---
title: "Update the connector stack"
description: "Reconnect the Deployz connector with new values, or update it to a newer template, without creating a second stack."
---

{/* Last checked against deployz commit 76a4b779 on 2026-10-23 */}

The Deployz connector stack is the CloudFormation stack you created during the install. Its name starts with `deployz-bootstrap-`. Each deployment has one connector stack, so you always update the existing stack. Don't create a second one: a new stack with the same name fails to create, and a second connector stack for the same deployment isn't supported.

You update the stack for one of two reasons:

| Why | How you find out | What changes |
| --- | --- | --- |
| [Reconnect the connector](#reconnect-the-connector) | The install page shows **Reconnect the existing connector**. | The connection values: `EnrollmentCode`, and usually `RelayCredential`. |
| [Update to a newer connector](#update-to-a-newer-connector) | Your software provider asks you to update the connector. | Only the template. Every parameter keeps its existing value. |

## Reconnect the connector

**Who:** you, on the install page and then in your AWS console.

The install page shows **Reconnect the existing connector** when a connector stack from an earlier attempt is still in your account and the deployment needs a new connection. This happens after you select **Retry connection**, or after your software provider sends you a new install link. The page shows **Update the connector stack. Do not create a new one.**, the stack name, and the values to enter.

<Warning>
Use the values on the page you have open now. If your software provider sends another new install link, the values change, and an update with the old values doesn't connect.
</Warning>

<Steps>
  <Step title="Sign in to the right AWS account">
    In the same browser, sign in to the AWS account that holds the connector stack, with an identity that can update CloudFormation stacks and IAM roles.
  </Step>
  <Step title="Open the connector stack">
    Select **Open connector stack in AWS**. The CloudFormation console opens in a new tab, in the deployment's Region, with the stack list filtered to the connector stack. Select the stack named on the install page, then select **Update**.
  </Step>
  <Step title="Replace the template">
    Select **Replace existing template**. If the install page shows a **Template URL**, choose the Amazon S3 URL option and enter it. Otherwise, keep the current template.
  </Step>
  <Step title="Enter the new values">
    Enter the **EnrollmentCode** from the install page. If the page shows a **RelayCredential**, enter it too. Keep every other parameter as it is, including `ControlPlaneUrl`, which the page shows as unchanged.
  </Step>
  <Step title="Submit the update">
    Acknowledge that AWS CloudFormation might create IAM resources, then submit the update.
  </Step>
  <Step title="Return to the install page">
    Go back to the install page tab. When the connector reconnects, the progress continues there.
  </Step>
</Steps>

## Update to a newer connector

**Who:** you, in your AWS console, when your software provider asks you to.

Deployz occasionally publishes a newer connector. Your software provider sees when one is available and sends you the steps, usually with a template URL. Updating is your decision, because the connector runs in your account. A newer connector can add actions that your software provider needs, and gives the connector the current permissions. See [Security and AWS access](/customers/security).

This update keeps the connector's existing credential, so you don't need new values.

<Steps>
  <Step title="Open the connector stack">
    Sign in to the AWS account that holds the connector stack. In the CloudFormation console, in the application's Region, select the connector stack, then select **Update**.
  </Step>
  <Step title="Replace the template">
    Select **Replace existing template**. If your software provider sent a template URL, choose the Amazon S3 URL option and enter it.
  </Step>
  <Step title="Keep every parameter value">
    For each parameter, keep the existing value (**Use existing value**). Don't change `RelayCredential`: a changed credential disconnects the connector.
  </Step>
  <Step title="Submit the update">
    Acknowledge that AWS CloudFormation might create IAM resources, then submit the update.
  </Step>
</Steps>

After the update, an application that's already installed keeps the roles it was created with and keeps working.

## If the update doesn't work

- **The stack isn't in the list.** Check that you're in the right AWS account and Region. If the connector stack was deleted, contact your software provider.
- **The update fails in CloudFormation.** Check the stack's **Events** tab for the reason, for example a policy in your organization that denies an IAM action. Fix the cause, then update again.
- **The install page still shows Still connecting after a reconnect.** Check that you entered the values from the page you have open now. If your software provider sent a newer link, open it and update the stack again with its values.
- **You created a second connector stack by mistake.** Delete the extra stack in CloudFormation, then update the original one as described above.

If none of these help, contact your software provider and quote the **Installation reference** from **Technical details** on the install page.
