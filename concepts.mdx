Deployz organizes your work around a few objects. Knowing which object owns what tells you where to find a setting or an action in the dashboard.

## Which object owns what

| Object | Owns | Doesn't own |
| --- | --- | --- |
| Application | Analysis, configuration defaults, releases, and the install link | Operations on a deployment |
| Customer | Contact details, invitations, links to that customer's deployments, and that customer's configuration overrides for each application | Operations on a deployment, the install link |
| Deployment | Status, every day-to-day action, failures and recovery, and its infrastructure details | The application's defaults, the customer's overrides |

In practice:

- To change how the application is analyzed, configured, or built, open the application.
- To deploy an update, roll back, restart, change one customer's values, or remove a deployment, open the deployment.

## Application

An application is one GitHub repository connected to Deployz. Each repository can be added once per organization. The application's page has three tabs:

- **Overview:** the application's status and its one next action.
- **Releases:** the versions Deployz has built.
- **Configuration:** the detected services, size presets, environment variables, and settings, on the **Resources**, **Size presets**, **Variables**, and **Settings** tabs. **Remove application** is on **Settings**.

Changes on **Configuration** reach deployments at different times:

- **Runtime environment variables** reach running deployments within minutes.
- **Build environment variables** apply to releases built after the change.
- **The migration command** applies to new deployments. An existing deployment keeps the command it was created with until you save a command in Deployz. Its next release deployment then uses the saved command. See [Database migrations](/prepare/migrations).
- **Size presets** apply only to new install links and new deployments.
- **The container port, the health check path, and services** (database, cache, and file storage) apply only to new deployments.

Existing deployments keep the size and resources they were created with.

Deployz analyzes the repository when you add the application, and again when you select **Re-analyze application** in the **More actions** menu (the three-dot button) in the application's header. Analysis decides whether the application fits the supported architecture. See [Application requirements](/prepare/requirements).

## Release

A release is a fixed version of your application, built from one commit. You give each release a version label, such as `v1.3.0`. Once a release is built, it doesn't change.

Creating a release doesn't update any deployment. You choose when each deployment moves to a new release. See [Create a release](/releases/create) and [Deploy an update](/operate/deploy-update).

A release can later show **Unavailable** when its build is no longer available. To deploy that version again, create a new release from the same commit.

## Deployment

A deployment is one application running in one AWS account, in one AWS Region. A test deployment is a deployment too. "Install" is the word for a deployment's first setup in that account. Each deployment has its own status, address, and history.

A deployment runs with your application's configuration defaults plus the customer's overrides. Overrides are stored per customer and application, so they apply to all of that customer's deployments of the application. See [Change a customer's configuration](/operate/configuration).

You choose a deployment's Region and size before it's installed. You can't change either one afterward. See [Deployment status and health](/operate/deployment-status) for what each status means.

## Test deployment

A test deployment is a deployment of your application in your own AWS account. It uses the same install page and AWS steps your customers use, so you can find problems before a customer does.

- It's free. Deployz doesn't bill test deployments, but AWS bills your account for the resources it uses.
- Each application can have one test deployment at a time.
- **Create install link** appears on the application's **Overview** after a test deployment succeeds. If you remove that test deployment before any customer deployment exists, **Create install link** goes away until a new test deployment succeeds. An install link you already created stays live.
- Invitations don't need a test deployment. You can invite a customer once the application has a built release.

See [Run a test deployment](/share/test-deployment).

## Customer

A customer is a record of a company or person you deploy to: a name, an email address, and an optional company name. Customers don't have a Deployz account. They act only on the install page and in their own AWS console.

Your organization's name is shown to customers as the publisher on the install page.

## Install link

An install link is a reusable link for one application. You share the same link with any number of customers. When a customer opens it, they choose an AWS Region and a size, enter any settings you've asked them to provide, enter their name and email, and confirm. Each confirmation creates a new customer record and a new deployment.

Each application has one live install link at a time. You can disable it and enable it again, regenerate it, or revoke it. See [Share an install link](/share/install-links).

## Invitation

An invitation is a link for one specific customer. You create it from the dashboard and can recommend a Region and size, but the customer makes the final choice. An invitation creates one deployment when the customer confirms it, and can't be used again after that.

An invitation expires 30 days after you create it. While it's active, you can revoke it from the customer's page. The invitation link includes a one-time token that Deployz shows only once, when you create it. See [Invite a specific customer](/share/invitations).

## Deployz connector

The Deployz connector is a small AWS Lambda function in the customer's AWS account. It carries out every change to the deployment there, and it connects outbound only. See [The Deployz connector](/how-it-works#the-deployz-connector) and [Reconnect or update the Deployz connector](/operate/connector).

## Organization and roles

An organization is your company's space in Deployz. It holds your applications, customers, deployments, and billing. When you sign up, Deployz creates an organization for you and makes you its owner. You can belong to more than one organization and switch between them in the dashboard.

Each member has one role: owner, admin, or member. Roles control only who manages the team and the organization. Every member can work with applications, deployments, and billing.

You manage members under **Team** in the dashboard. For details, see [Roles](/account/organization-and-team#roles).
