An AWS Region is the geographic location where a deployment's resources run, such as US East (N. Virginia). Each deployment runs in one Region, chosen when the deployment is created.

## Supported Regions

Deployz supports the 17 AWS Regions below, but you can install only into the Regions that are currently available for installs. The Region lists in the dashboard and on the install page show only those Regions. If a Region in this table doesn't appear in a list, you can't install into it.

## Who chooses the Region

| Deployment | Who chooses | How |
| --- | --- | --- |
| [Test deployment](/share/test-deployment) | You (the vendor) | You select the **AWS region** when you create it. |
| [Invitation](/share/invitations) | Your customer | You can recommend a Region. It's preselected and labeled **Recommended** on the install page. The customer makes the final choice. If the recommended Region is no longer available for installs, the install page shows no recommendation. |
| [Install link](/share/install-links) | Your customer | The customer selects a Region. Install links don't carry a Region recommendation. |

When there's no recommendation, the customer must select a Region before they can continue. Deployz doesn't choose one for them.

## You cannot change the Region later

The Region is fixed when the deployment is created. To move an application to a different Region, create a new deployment in that Region, then [remove the old one](/operate/remove). Data in the old deployment's database and file storage doesn't move with it.

## Cost varies by Region

AWS prices differ between Regions, so the same size can cost more in one Region than in another. The estimated monthly cost on the install page reflects the Region the customer selects. See [Regional differences](/share/sizes-and-cost#regional-differences).
