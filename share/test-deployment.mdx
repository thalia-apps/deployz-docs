A test deployment installs your application in an AWS account you control, through the same install page and AWS steps your customers go through. Run one before you share your application, so you find configuration and startup problems before a customer does.

## What a test deployment is

- **Free.** Deployz never bills a test deployment, and it doesn't need a subscription. AWS bills the account you install into for the resources it uses. See [Sizes and AWS cost](/share/sizes-and-cost).
- **One per application.** Each application can have one test deployment at a time. To start a new one, remove the existing test deployment first.
- **Yours to configure.** You choose the AWS Region and the size. Your customers choose these for their own deployments.
- **The same flow your customers use.** The test deployment has its own install link, opens the same install page, and creates the same Deployz connector and resources in AWS.

The application **Overview** offers **Create install link** only after a test deployment succeeds, or once the application has a customer deployment. A passing test is the signal that the application is ready to share.

## Before you start

You need:

- An application whose analysis has finished, with no required changes open on **Configuration**.
- A built release. The test deployment installs your application's newest built release. If the application doesn't have one yet, you can start the first build from the **Create test deployment** page. See [Create the test deployment](#create-the-test-deployment).
- An AWS account where you can create a CloudFormation stack with IAM resources. The requirements are the same as for a customer. See [Before you install](/customers/before-you-install).

## Create the test deployment

**Who:** you (the vendor), in the Deployz dashboard.

<Warning>
  You can't change a deployment's Region or size after you create it. To use a different Region or size, remove the test deployment and create a new one.
</Warning>

<Steps>
  <Step title="Open the application">
    In **Applications**, open your application. When it's ready, the **Overview** shows **Ready for a test deployment**.
  </Step>
  <Step title="Start the test deployment">
    Select **Start test deployment**. The **Create test deployment** page opens with your application selected.
  </Step>
  <Step title="Choose a customer record">
    In **Customer**, select an existing customer, or keep **Create new customer** and enter a name and email. You can use your own details. A new customer record appears in **Customers**, like any other customer.
  </Step>
  <Step title="Choose the Region and size">
    Select the **AWS region** to install into, then the **Size**. The **AWS region** list shows only the Regions available for installs, and the **Size** list starts at your application's minimum size. See [AWS Regions](/share/regions) and [Sizes and AWS cost](/share/sizes-and-cost).
  </Step>
  <Step title="Check the deployment checks and the release">
    Deployz runs its deployment checks as soon as the application is selected, and shows the result on the page. It also shows which release the test deployment installs.

    - If a check shows **Fix before deploying**, fix the issue, then return to this page.
    - If the application has no built release, select **Build release from commit**, followed by the short commit SHA. Deployz builds the first release from the commit it analyzed, and the page follows the build. To build a different commit, select **Go to Releases** instead. See [Create a release](/releases/create).
  </Step>
  <Step title="Create it">
    Select **Run free test deployment**. The button stays unavailable until the checks pass and a release is built. The text next to it says what it's waiting for.
  </Step>
</Steps>

If the application already has a test deployment, Deployz shows "This application already has a test deployment." Select **View the existing test deployment** to open it.

When the test deployment is created, **Deployment created** shows its install link. If your application needs values that your customers normally enter, select **Set up configuration** to enter them for this deployment.

You don't need to copy the link now. After you leave this page, the link stays on the test deployment's page, in the **Install link** card. Open it from **Deployments**.

The install link is valid for 30 days after you create the test deployment. The **Install link** card shows the expiry date. If the link expires before your AWS account connects, select **Issue new install link** on the deployment to make it valid for 30 more days. See [Reconnect or update the Deployz connector](/operate/connector#you-issue-a-new-install-link).

## Install it in your AWS account

**Who:** you, on the install page and in your AWS console.

1. Select **Open**, or copy the install link and open it in your browser.
2. On the install page, select **Connect AWS account**. The AWS console opens in a new tab, in the Region you chose.
3. Sign in to the AWS account you want to use, and create the stack.
4. Return to the install page and follow the progress. When the deployment is ready, select **Open application**.

These are the same steps your customers follow. [Install the application](/customers/install) describes each one.

## After the test

- **If it succeeds,** the application **Overview** shows **Ready to share**. Share it with an [install link](/share/install-links) or an [invitation](/share/invitations).
- **If it fails,** the **Overview** shows the **Test failed** badge, with **Test deployment failed**, or **The test deployment is disconnected** if Deployz lost the connection to it. Select **Review failure** to open the deployment and its recovery steps. See [Find your problem](/troubleshooting/overview).

The test deployment keeps running, and keeps using AWS resources, until you remove it. See [Remove a deployment](/operate/remove).

### Removing a passed test before you have customers

Removing the test deployment changes what the **Overview** offers, until you have at least one customer deployment:

- If you haven't created an install link yet, **Create install link** is no longer available. The **Overview** returns to **Ready for a test deployment**, and you need another successful test before you can create the link.
- An install link you already created keeps working. The **Overview** shows it with a warning that the link is live, and you can disable it there.

Once a customer deployment exists, removing the test deployment doesn't affect your install link.
