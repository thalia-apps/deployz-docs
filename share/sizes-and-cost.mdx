Every deployment uses one of three sizes: Small, Medium, or Large. The size sets the capacity of your application's containers, database, and cache. It's chosen when the deployment is created and can't be changed afterward.

AWS bills the account the deployment runs in. For a customer deployment, that's your customer's account. For a test deployment, it's yours. Deployz fees are separate. See [Pricing and billing](/account/billing).

## The three sizes

| | Small | Medium | Large |
| --- | --- | --- | --- |
| Each container | 0.25 vCPU, 512 MiB memory | 1 vCPU, 2 GiB memory | 2 vCPU, 4 GiB memory |
| Database (PostgreSQL 16 or MySQL 8.0) | `db.t3.micro`, 20 GB storage | `db.t3.medium`, 20 GB storage | `db.t3.large`, 20 GB storage |
| Cache (Valkey) | `cache.t4g.micro`, 1 node | `cache.t4g.small`, 1 node | `cache.t4g.medium`, 1 node |

- Each container runs as one copy. The web application and each background worker get the container size shown.
- Database storage starts at 20 GB and grows automatically up to 100 GB.
- A deployment includes a database or cache only when your application needs one.
- Every size creates the same set of resources. Only their capacity differs.

## Default size and recommended size

Each application has two size settings, and each install link and invitation has its own recommended size:

- **Default size** is an application setting. It's the size Deployz preselects whenever you create an install link, an invitation, or a test deployment for the application.
- **Minimum allowed size** is an application setting. It's the smallest size anyone can choose. Customers don't see sizes below it.
- **Recommended size** belongs to one install link or invitation. It starts at the default size, and you can change it when you create the link or invitation. Your customer sees it preselected on the install page, labeled **Vendor recommended**.

## Set the default and minimum size

**Who:** you (the vendor), in the Deployz dashboard.

Both settings start at Small.

1. Open your application, then select **Configuration**.
2. Select the **Size presets** tab. It shows each size's resources and estimated AWS cost side by side. The current default size is labeled **Default**, and sizes below the minimum are labeled **Below minimum**.
3. Under **Customer sizes**, choose the **Default size** and the **Minimum allowed size**. The default must be the same as the minimum or larger. If you raise the minimum above the current default, the default moves up to the new minimum.
4. Select **Save sizes**.

Changes apply only to install links, invitations, and deployments you create afterward. Existing deployments keep their size. Each install link and invitation keeps the sizes it had when you created it. To apply a new minimum to your install link, [regenerate it](/share/install-links#manage-the-link).

## Who chooses the size

| Deployment | Who chooses |
| --- | --- |
| [Test deployment](/share/test-deployment) | You |
| [Install link](/share/install-links) or [invitation](/share/invitations) | Your customer, at or above the minimum. Your recommended size is preselected and labeled **Vendor recommended**. |

<Warning>
  A deployment's size can't be changed after it's created. Updates, rollbacks, and restarts keep the same size. To use a different size, create a new deployment.
</Warning>

## Estimated monthly AWS cost

Deployz shows an estimated monthly AWS cost on **Size presets** and on the customer's install page. The install page estimate reflects the Region and size the customer selects. On **Size presets**, **Estimate details** names the Region the estimate uses. The estimates are approximate ranges in US dollars, based on on-demand AWS prices for 730 hours a month. They aren't a quote or a bill.

### Read the estimate

| What you see | Meaning |
| --- | --- |
| A range, such as `$65–$95 + usage` on **Size presets** | The baseline monthly cost of the resources Deployz can price. **+ usage** means some costs depend on how much the application is used, and aren't in the range. See [What the estimate leaves out](#what-the-estimate-leaves-out). |
| “Some resources could not be priced” | The deployment includes a resource that Deployz has no price for. The real cost is higher than the range. On **Size presets**, this note is under **Estimate details**. On the install page, it reads "Estimate is incomplete". |
| **Estimate unavailable** | Deployz couldn't produce an estimate. On the install page, this happens when the selected Region isn't available for installs. |

### Baseline cost by resource

<BaselineCosts />

Every deployment gets its own private network, with a load balancer and a NAT gateway. A NAT gateway lets the application reach the internet without being directly reachable from it. Together these cost about $45–$65 a month at any size, so they're most of the cost of a Small deployment.

For example, an application with a web container and a PostgreSQL database, and no cache or workers, is estimated at about:

| Small | Medium | Large |
| --- | --- | --- |
| $65–$95 | $125–$165 | $210–$260 |

These are illustrative figures for US East (N. Virginia). Check **Size presets** for your own application's estimate.

### How the estimate is rounded

Deployz multiplies each resource's range by the Region factor and rounds the result to whole dollars. It then adds up the resources and widens the total to multiples of $5: the low end is rounded down and the high end is rounded up. In the example above, the Small resources add up to $67–$95, which shows as $65–$95.

### Regional differences

Prices in other Regions are estimated with a coarse adjustment to the US East (N. Virginia) baseline.

### What the estimate leaves out

Some AWS costs depend on usage, so the estimate leaves them out:

- Files stored in file storage (Amazon S3) and data transfer
- Data processed by the NAT gateway
- Load balancer capacity used
- Database storage growth and backups
- Messages sent to and received from queues (**Preview**), and scheduled invocations (**Preview**)
- One-off tasks, such as migrations and scheduled jobs, which are billed by how long they run
- Outbound internet data transfer and data transfer between Availability Zones

The estimate also leaves out some smaller fixed costs of each deployment:

- Secrets in AWS Secrets Manager, such as the database credentials
- Application logs in Amazon CloudWatch Logs
- The NAT gateway's public IPv4 address (an Elastic IP address), which AWS charges for separately
- The resources of the Deployz connector

Workers are priced like the web container, as one always-running copy each. Queues and schedules are billed by usage only, so they add no fixed amount and show as usage-based.

Deployz fees and any external services your application uses are also not included.

To explain AWS costs to your customers, send them [Costs in your AWS account](/customers/costs).
